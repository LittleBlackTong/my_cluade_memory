# LLM 长期记忆机制的边界

**TL;DR**：LLM 的"长期记忆"不是一个统一系统，而是三层独立机制叠加。理解边界比相信它"自动会记住"更重要。

## 三层机制

### 1. 会话内上下文
- 范围：当前对话窗口
- 失效：会话结束、上下文压缩、超过 token 限制
- 用户无需操作

### 2. 内置记忆系统（auto-memory）
- 位置：`/Users/crazy/Library/Application Support/Claude-3p/.../memory/`
- 类型：user / feedback / project / reference
- 加载方式：每次会话开始自动注入 `MEMORY.md` 索引
- **写入**：由 LLM 在识别到值得保存的事实时显式写入
- **边界**：本会话中观察到该目录为只读挂载，无法直接写入。这可能由会话权限或系统策略决定，需在 schema 中说明

### 3. 用户文件系统中的持久化产物（如本 wiki）
- 完全由 LLM 读写，无系统限制
- 但**不会自动注入**——LLM 需要主动读取
- 用户可见、可独立使用（Obsidian、grep 等）

## 关键边界

| 误以为会发生 | 实际会发生 |
|---|---|
| 自动记住对话全部内容 | 仅显式写入的内容会被保留 |
| 下次会话"想起来" | 需通过读取 wiki/CLAUDE.md + index.md 主动恢复 |
| 三层会自动同步 | 三层独立，需要 LLM 在每次写入时手工协调 |

## 主动归档触发信号（推荐规则）

LLM 应主动提议归档（不需用户提示）：
- 用户分享关于自身的新事实（角色、偏好、约束）
- 用户给出明确反馈（"以后别这样"/"这次这样做对"）
- 用户提到跨会话还会用到的项目上下文
- 讨论中产生有价值的洞察或发现

LLM 不主动归档：
- 临时操作请求
- 纯事实问答
- 已有 raw/ 资料且无新综合的内容

归档前**默认先告知**用户，除非用户已开"自动归档"绿灯。
